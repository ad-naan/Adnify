# Adnify 多任务与会话信息架构

## 问题定义

旧会话面板把所有记录按更新时间平铺，并把“历史会话”和“对话分支”作为同级标签。这个结构适合单 Agent 连续对话，但无法回答多任务场景最重要的四个问题：

1. 现在有哪些任务正在运行、等待我处理或已经失败？
2. 某条会话属于哪个用户目标，是否是交接后的续跑？
3. 某个子 Agent 是由哪个任务派生的，执行到了哪里？
4. “任务分支”和“对话分支”有什么区别？

## 统一对象模型

```text
Workspace
└─ Task group（一个用户目标或一个 Plan）
   ├─ Execution node（一次独立上下文中的执行记录）
   │  ├─ Continuation（上下文交接后的续跑节点）
   │  ├─ Sub-task（父 Agent 派生的子 Agent 节点）
   │  └─ Conversation branch（该执行节点内部的备选回答路径）
   └─ Plan task（具有依赖关系、模型配置和产出物的调度节点）
```

术语约束：

- “任务”表示用户希望完成的目标，不再等同于一条会话。
- “会话”只作为执行记录存在；交接会创建新执行节点，但仍属于原任务。
- “子任务”是父执行节点派生的独立 Agent，会显示真实父子关系。
- “分支”仅指从某条消息产生的备选对话路径，归属于单个执行节点，不与任务并列。
- Plan 是一种带依赖图的任务组；其任务节点不再散落到普通会话历史中。

## 状态模型

统一状态优先级为：需要处理 > 失败 > 执行中 > 交接中 > 可继续 > 已停止 > 已完成。

| 状态 | 来源 | 用户含义 |
| --- | --- | --- |
| 需要处理 | 工具审批、等待用户输入 | 用户不操作就不会继续 |
| 失败 | stream/loop/handoff 失败 | 需要查看错误或重试 |
| 执行中 | 流式输出、工具执行、Plan task running | 后台仍在工作 |
| 交接中 | handoff transitioning | 正在创建或切换续跑节点 |
| 可继续 | 无活跃请求的普通会话 | 历史上下文仍可继续 |
| 已停止 | aborted/cancelled | 被主动终止 |
| 已完成 | loop 或 Plan task 完成 | 当前节点已收敛 |

任务组状态由组内优先级最高的节点聚合。因此一个子任务等待批准时，父任务组会直接进入“需要处理”，不会被埋在会话详情里。

## 界面结构

界面沿用软件既有的无边框语言：分区依靠浅层背景与留白，选中项和异常项依靠整块低饱和底色，父子关系通过缩进、展开图标与关系标签表达，不使用容器描边、选中下划线、状态竖线或树连接线。

任务中心仍从聊天面板顶部进入，但不再是普通历史抽屉。它包含三个视图：

- 关注：只显示正在执行、等待处理、交接中、失败以及当前打开的任务。
- 全部任务：按任务组展示完整历史，而不是按会话平铺。
- 当前分支：只展示当前执行节点的主线和备选对话路径。

每个任务组先显示聚合状态、更新时间和 Plan 进度；展开后显示执行树。树节点通过“续跑”“子任务”“计划任务”标签说明关系，并展示当前工具/待办、消息数和内部对话分支数。

### Agent 与 Plan 的模式边界

任务中心最终采用模式隔离，而不是把两类任务混在同一个抽屉：

- Agent 模式的“Agent 任务”只展示普通 Agent 会话、交接续跑和轻量子 Agent。
- Plan 模式继续使用 Plan 工作台自己的计划历史、依赖图、任务调度、执行日志与验收视图。
- Plan worker 线程不会出现在 Agent 任务列表中，避免用户误入计划内部执行上下文。
- 切换到 Plan 模式时会关闭 Agent 任务抽屉；切回 Agent 时也不会恢复之前的遮罩状态。
- 关系投影层仍支持 Plan 数据，供未来构建只读的跨计划总览，但不会改变当前 Plan 工作台的交互。

这种边界保证两者共享底层线程状态与父子关系模型，但在界面上各自负责不同工作：Agent 任务中心回答“哪些独立目标需要关注”，Plan 工作台回答“这个计划如何拆解、调度和验收”。

## 数据落地

`ChatThread` 新增以下持久化元数据：

- `origin: 'sub-agent' | 'handoff'`：明确执行节点类型。
- `parentThreadId`：记录直接父执行节点。
- `rootThreadId`：记录稳定的顶层任务链。

新子 Agent 和新交接会话创建时直接写入关系元数据。旧数据仍通过 `handoffResume.sourceThreadId` 和父消息工具调用中的 `subAgentThreadId` 尽量恢复关系；无法恢复的旧记录才作为独立任务显示。

## 后续演进

当前版本先解决可见性和归类。后续可以在同一模型上增加：

1. 任务置顶、归档、标签和自定义任务组。
2. 全局通知策略，例如“仅等待我处理时提醒”。
3. Plan 依赖图和普通子任务树的统一关系画布。
4. 任务级耗时、Token、工具调用和文件变更统计。
5. 任务组级批量停止、重试、导出和删除确认。
